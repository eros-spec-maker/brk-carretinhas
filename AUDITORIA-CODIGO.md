"# Auditoria de Qualidade de C\u00f3digo \u2014 BRK Carretinhas\n**Data:** 10/09/2026 \u00b7 **Escopo:** qualidade, organiza\u00e7\u00e3o e manutenibilidade (sem altera\u00e7\u00f5es)\n**Base analisada:** bundle de produ\u00e7\u00e3o publicado (index-U94GMNP5.js, ~504KB + CSS 74KB) \u2014 o c\u00f3digo-fonte original n\u00e3o est\u00e1 espelhado (GitHub 2-way sync pendente, Issue #10), ent\u00e3o nomes de arquivos/vari\u00e1veis originais n\u00e3o s\u00e3o vis\u00edveis; localiza\u00e7\u00f5es abaixo referem-se a componentes/contextos identific\u00e1veis no bundle.\n\n## O que est\u00e1 funcionando bem (preservar)\n- Skeleton loaders (32 usos) e keyframes dedicados (skeleton-shimmer, fade-in/out, slide-in/out) \u2014 motion bem implementado\n- `loading: lazy` centralizado num \u00fanico lugar (componente de imagem compartilhado)\n- Token de sess\u00e3o admin em `sessionStorage` (morre com a aba) \u2014 padr\u00e3o correto\n- Wrapper de API admin com catch unificado retornando `{data, status}`\n- sitemap.xml / robots.txt / llms.txt coerentes com as rotas reais (`/modelo/:id` respondem 200)\n- Entidades PT-BR consistentes (Carreta, Avaliacao, Orcamento)\n\n## P0 \u2014 pode causar quebra/vulnerabilidade\n**Nenhum encontrado nesta auditoria.** As rotas respondem, n\u00e3o h\u00e1 rotas mortas anunciadas no sitemap e o bundle carrega \u00edntegro. (CORS do gateway j\u00e1 rastreado na Issue #11 \u2014 \u00e9 limita\u00e7\u00e3o de plataforma, n\u00e3o do c\u00f3digo.)\n\n## P1 \u2014 dificulta manuten\u00e7\u00e3o / pode gerar bugs\n\n### P1-1. Componente admin gigante (~758 linhas, 12 useState)\n- **Arquivo:** componente admin (`function ES` no bundle \u2014 painel `/admin`)\n- **Trecho:** login + desafio anti-bot + gerenciamento de sess\u00e3o + CRUD de carretas + lista de or\u00e7amentos + logout + wrapper de API, tudo num \u00fanico componente com 12 hooks\n- **Problema:** responsabilidades misturadas (autentica\u00e7\u00e3o, dados, formul\u00e1rio e UI)\n- **Impacto:** qualquer mudan\u00e7a no admin toca no mesmo bloco; risco alto de regress\u00e3o cruzada; imposs\u00edvel testar pe\u00e7as isoladas\n- **Solu\u00e7\u00e3o:** extrair `AdminLogin`, `AdminDashboard`, `CarretaForm`, `OrcamentosList` + hook `useAdminApi` (o wrapper `S` j\u00e1 existe isolado \u2014 promov\u00ea-lo a hook pr\u00f3prio)\n\n### P1-2. Acesso a dados duplicado\n- **Arquivo:** cat\u00e1logo p\u00fablico e painel admin (duas chamadas `Carreta.list('-created_date', 100)` id\u00eanticas; `Avaliacao.filter` repetido)\n- **Problema:** l\u00f3gica de carregamento copiada entre componentes em vez de hook/servi\u00e7o compartilhado\n- **Impacto:** corre\u00e7\u00e3o em um lugar n\u00e3o corrige o outro (ex.: pagina\u00e7\u00e3o, tratamento de erro divergente); dois pontos de verdade\n- **Solu\u00e7\u00e3o:** hooks compartilhados `useCarretas()` e `useAvaliacoes(carretaId)` com loading/error centralizados\n\n### P1-3. Tratamento de erro inconsistente\n- **Arquivo:** v\u00e1rias fun\u00e7\u00f5es do app\n- **Trecho:** ~4 `catch` que s\u00f3 fazem `console.error` (usu\u00e1rio n\u00e3o v\u00ea nada, estado pode ficar travado); 1 `alert('Erro ao salvar.')` nativo; login usa mensagem inline\n- **Impacto:** experi\u00eancia de falha imprevis\u00edvel; `alert` bloqueia a UI e fere o padr\u00e3o de motion; erros silenciosos escondem bugs\n- **Solu\u00e7\u00e3o:** helper \u00fanico de notifica\u00e7\u00e3o (toast/mensagem inline) usado por todos os fluxos; nenhum `catch` sem feedback ao usu\u00e1rio + log estruturado\n\n### P1-4. Cores m\u00e1gicas espalhadas\n- **Arquivo:** todo o app (classes de estilo)\n- **Trecho:** `#1A1C1E` \u00d798, `#A0AAB2` \u00d757, `#FF5F1F` \u00d756, `#F4F5F7` \u00d725 em classes arbitr\u00e1rias\n- **Impacto:** trocar a cor da marca = 56+ edi\u00e7\u00f5es espalhadas; risco de inconsist\u00eancia visual em mudan\u00e7as futuras\n- **Solu\u00e7\u00e3o:** tokens de tema (vari\u00e1veis CSS ou config do Tailwind: `bg-ink`, `text-brand`\u2026), migrando gradualmente\n\n## P2 \u2014 melhoria de qualidade\n\n### P2-1. JSX repetido\n- **Trecho:** bloco label+input id\u00eantico \u00d73 (mesmas classes); bot\u00e3o de or\u00e7amento/`wa.me` repetido\n- **Impacto:** mudan\u00e7a visual exige ca\u00e7ar todas as c\u00f3pias\n- **Solu\u00e7\u00e3o:** componentes `Field`, `OrcamentoButton`, `SpecRow`\n\n### P2-2. Estado redundante de sess\u00e3o\n- **Trecho:** `brk_admin_session` (\"ok\") + `brk_admin_token` no sessionStorage \u2014 dois flags pro mesmo conceito\n- **Impacto:** risco de estados divergentes (um set, outro n\u00e3o)\n- **Solu\u00e7\u00e3o:** manter s\u00f3 o token; backend \u00e9 o validador real (o front s\u00f3 decide qual tela mostrar)\n\n### P2-3. Keyframes de anima\u00e7\u00e3o duplicados conceitualmente\n- **Arquivo:** CSS (74KB)\n- **Trecho:** `enter/exit` (shadcn) coexistem com `fade-in-anim/fade-out-anim` custom; `slide-in/out-right` vs `accordion-down/up`\n- **Impacto:** duas conveni\u00e7\u00f5es de anima\u00e7\u00e3o no mesmo app; curva de aprendizado e revis\u00e3o desnecess\u00e1rias\n- **Solu\u00e7\u00e3o:** padronizar numa \u00fanica conven\u00e7\u00e3o de nomes/dura\u00e7\u00f5es\n\n### P2-4. Logging sem estrutura\n- **Trecho:** `console.error/warn` espalhados, sem prefixo nem contexto padronizado\n- **Impacto:** quando chegar observabilidade (Sentry, Issue #5), cada ponto precisa ser retrabalhado\n- **Solu\u00e7\u00e3o:** helper `logger(evento, contexto, n\u00edvel)` \u2014 j\u00e1 prepara o terreno pro Issue #5\n\n## P3 \u2014 est\u00e9tica de c\u00f3digo\n\n- **P3-1.** Objeto default de formul\u00e1rio de carreta com campos vazios nomeados de forma gen\u00e9rica (`TS` no bundle) \u2014 nomear explicitamente `EMPTY_CARRETA_FORM` no fonte\n- **P3-2.** Entidades PT-BR (Carreta/Avaliacao/Orcamento): conven\u00e7\u00e3o consistente \u2014 **manter**; apenas documentar no AGENTS.md\n- **P3-3.** CSS \u00fanico de 74KB: aceit\u00e1vel para a plataforma; revisar classes n\u00e3o usadas quando houver pipeline pr\u00f3prio (Knip, Issue #6)\n\n## Limita\u00e7\u00f5es desta auditoria\n- Bundle minificado: nomes originais de arquivos/fun\u00e7\u00f5es/vari\u00e1veis n\u00e3o vis\u00edveis; an\u00e1lise de organiza\u00e7\u00e3o de pastas e imports n\u00e3o utilizados exige o c\u00f3digo-fonte\n- Backend functions: s\u00f3 comportamento observ\u00e1vel (erros limpos, rate limit OK, challenge OK) \u2014 fonte n\u00e3o leg\u00edvel de fora\n- **Recomenda\u00e7\u00e3o:** ativar o GitHub 2-way sync (Issue #10) e refazer esta auditoria linha a linha sobre o fonte real\n\n## Ordem recomendada de execu\u00e7\u00e3o (quando autorizado)\nP1-3 (erro consistente) \u2192 P1-2 (hooks de dados) \u2192 P1-4 (tokens de tema) \u2192 P1-1 (split do admin, por \u00faltimo pois beneficia dos anteriores) \u2192 P2s \u2192 P3s.
